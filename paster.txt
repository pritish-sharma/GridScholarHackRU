# Master Project Specification: DeltaMetrics

**Target Event:** HackRU (Rutgers NB)
**Target Tracks:** Social Good, Education, Gemini API Sponsor

## 1. Core Concept & Value Proposition

**The Problem:** College admissions metrics (APs, GPAs) lack socioeconomic context. Under-resourced students are forced to use their limited 650-word personal statement to explain structural disadvantages (low AP offerings, high counselor ratios, working to support family), while wealthy students use that space to showcase personality.
**The Solution:** DeltaMetrics is a 2-page web application that acts as an "Automated Data-Counselor." It takes basic student inputs, queries federal databases to determine the student's local environmental baseline, and generates a verified, quantitative "Context Report" that applicants can attach to the "Additional Information" section of the Common App.
**Why it beats generic AI wrappers:** Standard LLMs generate subjective, unverifiable narratives that admissions officers ignore. DeltaMetrics uses deterministic data science (Python, Pandas, federal datasets) to calculate exact percentile benchmarks (e.g., "100% Opportunity Utilization"), using the Gemini API solely to interpret the math into a professional summary.
**Ethics & Legality:** 100% legal (uses public-domain US government APIs/datasets) and highly ethical (aligns with SCOTUS guidelines allowing the consideration of individual adversity and distance traveled).

## 2. Product Features & User Flow

**Screen 1: Applicant Input Form (Frontend)**
A clean form collecting four data points:

* High School Name (Dropdown/Search)
* Home Zip Code
* Number of AP/Honors classes taken
* Hours spent per week on non-academic "survival" tasks (work, family care, commuting)

**Screen 2: The Context Report Dashboard (Frontend/PDF Export)**
A printable, scannable dashboard displaying three core elements:

1. **Opportunity Utilization Chart:** A bar chart/gauge (via Recharts/Chart.js) showing APs taken vs. total APs offered at their specific school.
2. **Environmental Baseline Metrics:** Three specific data points pulled from the backend:
* Local High School Counselor-to-Student Ratio vs. State Average.
* Zip Code Median Income vs. State Average.
* Calculated "Weekly Time Deficit" (hours lost to survival tasks).


3. **The Gemini Context Statement:** A 150-word, highly objective paragraph generated by the Gemini API summarizing the student's resilience based *strictly* on the data above.

## 3. Technical Architecture & Tech Stack

**Frontend (Student A - UI/UX Focus)**

* **Framework:** React (Vite) or Next.js.
* **Styling:** Tailwind CSS.
* **Visualization:** Recharts or Chart.js for the utilization gauges/bar charts.
* **Deployment:** Vercel (Auto-deploys via GitHub).

**Backend (Student B - Data Science Focus)**

* **Framework:** Python with FastAPI.
* **Data Handling:** Pandas and NumPy.
* **AI Integration:** `google-genai` SDK.
* **Deployment:** Render (Deployed as a Web Service from a GitHub repo with a `requirements.txt`).
* **Hackathon Optimization (Crucial):** Do not live-scrape the NCES database. Download the CSV of local/state high schools from the National Center for Education Statistics (NCES) and the US Census beforehand. Load this CSV into a Pandas dataframe on backend startup for instant querying.

## 4. Division of Labor

**Frontend Developer Tasks:**

* Initialize the React/Next.js repository.
* Build the routing (Page 1 -> Page 2).
* Create the Input Form UI and handle state.
* Create the Dashboard UI (Metric cards, Chart component, Gemini text box).
* Write the API `fetch` calls to send form data to the FastAPI backend and await the JSON response.
* Implement a "Print to PDF" button (using standard CSS `@media print` or a library like `html2pdf`).

**Backend Developer Tasks:**

* Initialize the FastAPI repository and configure CORS middleware (to allow the frontend to communicate with the backend).
* Clean and format the NCES/Census CSV files; write a function to search the Pandas dataframe by High School Name / Zip Code.
* Write the math functions: calculate "Opportunity Utilization" (Taken / Offered) and "Time Deficit."
* Integrate the Gemini API.
* Build the main `POST` endpoint that accepts frontend inputs, runs the calculations, formats the prompt, calls Gemini, and returns the compiled JSON payload to the frontend.

## 5. Gemini API Prompt Architecture

The backend must format the dynamic data into this exact prompt structure before sending it to Gemini:

> "You are an expert college admissions counselor. Take this student's empirical data: [Insert Pandas calculated data: e.g., High school offers 3 APs, student took 3 (100% utilization); works 20 hours/wk; Zip code median income $40k vs state avg $85k; Counselor ratio 1:500]. Write a 150-word, highly objective, professional summary of this student's 'Distance Traveled' and resilience for a college admissions officer. Do not invent details. Do not be overly dramatic. Use the quantitative data provided to highlight their grit and contextualize their academic performance."

## 6. Hackathon Execution Strategy

* **Rule #1: Localhost First.** Do not touch Vercel or Render until the app works completely on `localhost:3000` (Frontend) communicating with `localhost:8000` (Backend).
* **Rule #2: Pre-record the Demo.** The moment the app functions locally, record a 2-minute screen-capture demo showcasing a "High Resource Student" vs. a "Low Resource Student" to prove the dynamic nature of the context engine.
* **Rule #3: Deploy Last.** Only attempt cloud deployment in the final hours once the core functionality is locked and recorded.
